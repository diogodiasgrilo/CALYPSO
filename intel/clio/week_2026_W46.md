### Recommendation 2: Implement Delta-Floor Fallback to `_calculate_strikes` When Chain Under-Hydrated (Existing Code Gap)

**Data basis:** Nov 9 E#2 (14:15 ET): "delta-target strike selector anchored to 8δ but resolved to a call short at 7600 with only 2.6δ — below the 4.0δ minimum floor. Skip reason explicitly states 'chain under-hydrated, picked near-worthless far-OTM strikes.'" This matches the identical failure mode documented in W30 (Jul 23) and W40 (Sep 30) where Polygon returned sparse but non-null far-OTM greeks (1.9–3.2δ), preventing the existing outage-triggered fallback from firing.

**Root cause (confirmed across 3 independent events — W30, W40, W46):** The fallback to parent `_calculate_strikes` triggers only on Polygon outage (null/missing greeks). When Polygon returns a valid but far-OTM greek value below the 4.0δ floor, the fallback does not fire — the entry skips instead. This is a code-level gap.

**Config/code recommendation:** Modify `bots/hydra/brandon/` `delta_target_strike_selection` logic: when resolved delta falls below `delta_floor` (4.0δ) and the cause is sparse chain rather than Polygon outage, trigger the parent `_calculate_strikes` fallback rather than skipping. Alternatively, add a `delta_floor_fallback_enabled: true` config parameter that routes under-hydrated entries to OTM-multiplier-based strike selection (MKT-024 2.5× call / 2.75× put) as the fallback.

**Expected impact:** Nov 9 E#2 would have resolved to a placement rather than a skip. Across the three documented events (W30 Jul 23, W40 Sep 30, W46 Nov 9), the under-hydrated delta-floor skip produced zero entries where entries may have been viable at OTM-multiplier distances.

**Confidence: HIGH.** Three independent identical failure events across 3 different weeks confirm this is not a one-off edge case.
